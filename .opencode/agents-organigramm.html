Querverbindungen — wer wen braucht

Die Pfeile im Baum sind Delegation. Diese Übergaben laufen quer und sind der Grund, warum das Manifest Dateien an genau einen Agenten hängt.

game → meshes
Braucht ein neues Mesh, fragt es meshes und hält an — ein selbst gebautes Mesh ohne Registry-Key ist der Fehler, der hier schon zweimal Zeit gekostet hat.
game → merge
Registry-Zeile, Router-Eintrag oder package.json fehlen: anhalten und melden, das ist Sache des Merge-Schritts.
game → apk
Änderung ist gebaut und committet; apk macht daraus build/singular80.apk und installiert sie.
apk ⇄ device-debug
Hände: apk baut und deployt, device-debug spielt ferngesteuert, liest Logcat und misst gfxinfo/meminfo. Ein Fix, der im Simulator grün ist, zählt erst nach dem Gerätetest.
device-debug → merge
Befund mit Ausgabe, nicht Vermutung. Braucht er Code, der die geteilten Registry-Dateien anfasst, ist das ein Befund für den Menschen, kein Selbstumbau.
meshes → merge
Jeder neue Mesh-Key wandert durch asset_registry.gd — die eine geteilte Datei, die eine Mesh-Änderung wirklich braucht.
dashboard → merge
Ändert buildPrompt in runner.ts, gilt die Worktree- und Scope-Regel aus AGENTS.md für den Auftrag, der daraus entsteht.
merge → Besitzer
Der Merge ist das Tor: ein voller grüner Lauf, oder ein Bericht an den Menschen. Kein Agent mergt auf grünem Teilgebiet, wenn der Gesamtlauf rot ist.

Datei-Eigentum — wer welche Datei anfasst

Scopes nach Agent — 26 Bahnen

So verteilt scopes.mjs die 26 Scopes. Ein Vorschlag bekommt seinen primären Scope vorhergesagt; danach entscheidet scopesConflict, ob er neben einem laufenden Run starten darf.

game
  • arena · tetris · poker · freecell · dame
  • crystal3d · horserunner · dragonrpg · dragonflight
  • pang · metro3d · 2048 · candy3d · siedler · merge3d
  • 4 Varianten (christmas, halloween)
  • content — Content-Packs
dashboard
  • dashboard — Dashboard & Server
meshes
  • meshes — Meshes & LOD-Stufen
merge
  • tooling — Werkzeuge & Manifest
lobby kein Agent
  • lobby — Lobby & Kategorien
build kein Agent
  • core — Kernlogik & Basisklassen
  • tests — Test-Harness

Lücke: die Scopes lobby, core und tests verweisen im Manifest auf die Agenten lobby und build — für beide gibt es keine Datei unter .opencode/agents/. Ein Auftrag mit diesem primären Scope läuft damit ohne den Subagenten, dem das Manifest die Dateien zuschreibt, und der Merge-Schritt ist die einzige Schranke.

Was nicht in diesem Organigramm steht

explore · general
Feste Bestandteile der OpenCode-Werkzeugkette, nicht von diesem Projekt definiert. Sie kennen kein Scope, keine Dateieigentumsregel und kein Merge-Gate — für echte Änderungen gehört die Arbeit an einen der sechs Agenten oben.
Die Leitsitzung selbst
Ebene 1. Sie delegiert, prüft am Ende einmal den ganzen Baum und ist die Instanz, die committet und pusht. Ein Subagent prüft nichts — das ist die ausdrückliche Arbeitsteilung, kein Versehen.
